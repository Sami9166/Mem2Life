# 인수인계 — 2026-08-02

`gemini-integration` 브랜치에서 한 작업과, 이어받을 사람이 알아야 할 것들.

프로젝트 전체 배경·아키텍처는 저장소 바깥 `CLAUDE.md`가 단일 소스다. 이 문서는
**오늘 바뀐 것과 다음에 할 것**만 다룬다.

## 1. 한 줄 요약

녹화부터 답변까지 전 경로가 실제 API로 한 번 끝까지 돌았다. **다만 답변이 아직

## 2. 지금 동작하는 것

```
글래스 녹화 → 30초 mp4 청크 + PCM 스트림 업로드 → /end
   ↓ (mock-backend가 자동 트리거)
tools/ingest_from_upload.py
   ├ PCM → WAV → RTZR 실전사 (화자분리)
   ├ 청크 concat → 키프레임 추출 (사건 경계 탐지)
   ├ 키프레임 → Gemini VLM 장면 캡션
   ├ 전사록 + 캡션 → Gemini LLM 요약
   └ 볼트 sessions/YYYY-MM-DD_HHMM_제목.md
   ↓
mem2life-recall (CLI 또는 /recall/query)
   ├ 하이브리드 검색 (BM25 + 임베딩) → coarse-to-fine
   ├ Gemini 자연어 답변 생성
   └ 근거 부족 시 → 영상 클립 잘라 Gemini 재조회
   ↓
   ❌ 여기서 끊긴다. 앱이 이걸 안 부른다.
```

외부 연동 5종(RTZR STT / Gemini 캡션 / Gemini 요약 / Gemini 답변 / Gemini 영상
재조회) 전부 실제 호출로 확인했다. 검증에 쓴 입력·출력 원본은 저장소 바깥
`검증자산_2026-08-02/`에 있다(합성 데이터 — README 참고).

**API 키 없이도 전부 끝까지 돈다.** 모든 외부 연동이 2단계 폴백을 따른다:
키가 없으면 생성 시점에 스텁/템플릿으로 교체, 키는 있는데 호출이 실패하면
(429/5xx/네트워크) 그 건만 스텁으로 대체하고 파이프라인은 계속 간다.

## 3. 다음 작업 — 글래스 질의 UI + TTS

답변이 사용자에게 닿으려면 이것 하나가 남았다. `android/.../MainActivity.kt`의
`QueryScreen()`이 현재 안내문만 띄우는 placeholder다.

### 앱이 해야 할 일

1. 터치패드 입력 → 질문 텍스트 확보 (음성 질의는 Vuzix Speech SDK 검토 단계, 미착수)
2. `POST {backend}/recall/query` 호출
3. 응답의 **`glass` 필드만** 보고 화면 구성 + TTS 재생

### 계약 — `glass` 필드

요청:

```json
{ "question": "카페에서 얼마 나왔지?", "reference_date": "2026-08-02" }
```

`reference_date`는 생략 가능(생략 시 서버의 오늘). `"어제"`, `"3일 전"` 같은
상대 시각 표기의 기준이 된다.

응답에서 앱이 볼 부분:

```json
{
  "glass": {
    "status": "answered",
    "status_label": "기록 확인됨",
    "tts_text": "아까 읽고 계시던 책의 제목은 침묵의 봄입니다.",
    "display_text": "아까 읽고 계시던 책의 제목은 침묵의 봄입니다.",
    "evidence": [
      {
        "label": "오늘 7초 · 책_대여_약속",
        "video_link": "/.../session_video.mp4@00:07"
      }
    ]
  }
}
```

근거를 못 찾은 경우:

```json
{
  "glass": {
    "status": "not_found",
    "status_label": "기록에 없음",
    "tts_text": "그건 기록에 없어요. 대화에서도 화면에서도 확인되지 않았습니다.",
    "display_text": "기록에 없음 — 대화·화면 어디에서도 확인되지 않았습니다.",
    "evidence": []
  }
}
```

| 필드 | 쓰임 |
|---|---|
| `status` | `answered` / `answered_from_video` / `not_found`. 아이콘·색 분기용 |
| `status_label` | 화면 상단에 그대로 띄울 한국어 문구 |
| `tts_text` | **스피커로 그대로 읽으면 된다.** 인용·경로·대괄호는 이미 제거됨 |
| `display_text` | 화면 본문. 역시 인용 표기 없음 |
| `evidence` | 근거 최대 2건. `label`은 그대로 띄우고, `video_link`가 있으면 탭 시 그 구간 재생 |

**`tts_text`와 `display_text`는 왜 나뉘어 있나**: 같은 값일 때가 많지만 계약상
분리돼 있다. 음성은 표기 문자를 걷어낸 형태고(위키링크 대괄호 제거,
`video@01:23` → "1분 23초 지점"), 화면은 표기를 살릴 여지를 남긴 것이다.
`tts_text`를 화면에 쓰거나 `display_text`를 읽어도 지금은 티가 안 나지만,
용도대로 쓰는 게 나중에 안전하다.

**앱이 하지 않아도 되는 것**: 인용 문구 잘라내기, sentinel 제거, 타임스탬프
포맷팅, 근거 개수 제한. 전부 백엔드가 이미 했다. 반대로 **줄바꿈(워드랩)은
앱이 해야 한다** — 폰트 메트릭은 앱만 안다.

최상위 `tts_text`/`answer_text`/`citations`/`fallback` 필드도 그대로 있지만
CLI·회귀 테스트·문제 추적용이다. 앱은 `glass`만 보면 된다.

## 4. 걸려 넘어질 만한 것들

### 4.1 API 키 없이 돌리면 답변이 아주 길다

`GEMINI_API_KEY`가 없으면 답변 생성이 템플릿 생성기로 폴백하는데, 이건 검색된
근거 문장 3개를 그대로 이어붙인다. 내용은 정확하지만 **480×480 화면에 절대 안
들어가고 TTS로 읽으면 1분 가까이 걸린다.** 실제 관측된 길이가 200자를 넘는다.

Gemini가 붙으면 1~2문장으로 나온다. UI를 만들 때 이 점을 감안하되(스크롤 필요),
데모/시연은 키를 넣고 돌리는 것이 전제다.

### 4.2 Gemini 무료 티어가 하루 20회다

파이프라인 1회 실행이 캡션 N + 요약 1, 질의 1회가 답변 1(+ fallback 시 재조회 1).
반복 디버깅하면 금방 소진된다. 소진되면 429가 나는데, **파이프라인은 죽지 않고
스텁으로 폴백한다**(그렇게 만들어놨다) — 다만 답변 품질이 조용히 템플릿으로
떨어지므로 "왜 갑자기 답이 이상하지?" 싶으면 한도부터 의심할 것.

호출을 아끼려면 `tools/ingest_from_upload.py --no-captions --no-summary`.

### 4.3 전사록 타임스탬프 관례가 두 가지다 (미결)

| | `## 전사록` 표기 |
|---|---|
| `testdata/mock_vault/` (손작성) | `[15:00:00]` — 벽시계 시각 |
| 실제 ingest 산출물 | `[00:00:07]` — 세션 시작 기준 경과 시간 |

`recall/vault/chunking.py`의 `_to_video_offset()`이 `start_sec`은 양쪽 다 올바르게
정규화하므로 **검색과 영상 링크는 문제없다.** 하지만 `timestamp_label`을 시각으로
표시하면 실제 산출물에서 "오늘 00:00"(자정)이라는 거짓말이 된다.

그래서 표현 계층은 `timestamp_label`을 안 쓰고 `start_sec` 기반 오프셋만 쓴다
(`recall/present/glass.py`의 `_offset_phrase` 주석 참고). **관례 자체를 어느 쪽으로
통일할지는 미결.** 벽시계로 통일하면 "어제 오후 3시쯤 뭐 했지?" 같은 시각 질의에
유리해서 결정할 값어치가 있다.

### 4.4 임베딩이 아직 해시 스텁이다

의미 유사도가 아니라 해시 기반이라, 전사록과 어휘가 거의 안 겹치는 패러프레이즈
질문은 **실제로 기록에 있어도 "기록에 없음"으로 답할 수 있다.** 라이브 시연에서는
대본 문구를 그대로 쓰거나 최대한 비슷한 어휘로 질문할 것.

### 4.5 화자분리 정확도 미검증

RTZR이 화자1/화자2로 나누기는 하는데, 검증에 쓴 샘플이 합성 음성(같은 TTS 목소리
피치만 변조)이라 경계가 부정확했다. **실제 사람 두 명으로는 아직 확인 안 됐다.**

### 4.6 이 개발 환경에서는 Kotlin 컴파일 검증 불가

JDK/Android SDK가 없다. 백엔드는 `uv run pytest`로 끝까지 검증되지만 android는
정적 리뷰까지만 가능하다. 실제 빌드는 Android Studio에서.

## 5. 직접 돌려보기

```bash
cd Mem2Life/backend
uv sync

# 전체 테스트 (API 키 불필요)
uv run pytest            # 257 passed, 3 skipped, 1 xfailed
uv run ruff check . && uv run ruff format --check .

# 질의 (mock_vault 기준)
uv run mem2life-recall ask "어제 민수랑 숙소 예산 얼마로 정했지?" --vault testdata/mock_vault

# 서버로 띄우기 (앱이 붙을 대상)
uv run mem2life-recall serve --vault testdata/mock_vault
#   POST /recall/query, GET /health
```

실제 API를 쓰려면 `backend/.env`에 `RTZR_CLIENT_ID`/`RTZR_CLIENT_SECRET`/
`GEMINI_API_KEY`. `.env.example` 참고. 없으면 자동으로 스텁이라 테스트는 그대로 통과한다.

업로드 세션 → 볼트 경로를 재현하려면 저장소 바깥 `검증자산_2026-08-02/README.md`에
명령어가 있다.

## 7. 브랜치 상황 (주의)

**`main`에 백엔드 성과물이 하나도 없다.** android만 최신이다.

| 브랜치 | 내용 |
|---|---|
| `origin/main` | android만 최신. 백엔드는 DB·키프레임·Gemini 전부 빠진 옛 상태 |
| `origin/vuzix-blade2` | 실질적 통합 브랜치. postgres 흡수 + 업로드 글루 + 앱 홈 화면 |
| `gemini-integration` | 이 문서의 작업. `vuzix-blade2` 기준 |

데모 전에 `main`으로 모으는 정리가 필요하다.
